GITHUB · FIȘIERE MARI

Git nu este potrivit pentru fișiere binare mari.

Git păstrează istoricul versiunilor. Pentru binare mari, modificările pot însemna copii complete în istoric, nu diferențe compacte ca în cazul textului.

DE CE EVITĂM BINARELE?

Istoric voluminos și operații lente

Clone și fetch lente, istoric care crește, diffs/merge aproape inutile pentru checkpoints, arhive și imagini.

CÂND ARE SENS?

Artefacte mici și stabile

Logo-uri, imagini de documentație, fixture-uri de test și exemple mici necesare pentru reproducere. Nu orice binar este o problemă.

ALTERNATIVE

Git LFS / Hub / object storage

LFS păstrează pointere în Git; fișierele mari se descarcă separat. Pentru modele: Hugging Face Hub; pentru volume masive: S3 sau echivalent.

OPENROUTER · API REAL

Același prompt, modele diferite. Și rezultate diferite.

Endpoint real: POST https://openrouter.ai/api/v1/chat/completions · documentație ↗

import os, requests
url = "https://openrouter.ai/api/v1/chat/completions"
headers = {"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"}
models = ["google/gemini-2.5-flash", "qwen/qwen3-32b"]
prompt = "Explică pe scurt de ce cerul este albastru."
for model in models:
    for trial in range(2):
        r = requests.post(url, headers=headers, timeout=90,
          json={"model":model,"messages":[{"role":"user","content":prompt}],
                "temperature":0.8})
        r.raise_for_status()
        print(model, trial, r.json()["choices"][0]["message"]["content"])

Modelele generative sunt de regulă nedeterministe: sampling-ul poate produce răspunsuri diferite chiar pentru același model și prompt. temperature=0 reduce variația, dar nu garantează reproducibilitate perfectă.

OPENROUTER · EMBEDDINGS

Similaritatea cosinus: comparăm direcții.

Un embedding reprezintă textul ca vector numeric. Similaritatea cosinus măsoară unghiul dintre doi vectori, nu diferența dintre lungimile lor.

Propoziții→Vectori→cos(θ) = (a·b)/(|a||b|)→Ranking

+1

Direcții identice (similaritate maximă).

0

Vectori ortogonali; fără aliniere unghiulară.

−1

Direcții opuse. În embeddings, scorurile trebuie interpretate relativ, nu ca probabilități.

Exemplu: „Pisica doarme” vs „Un motan se odihnește” ar trebui să fie mai apropiate decât „Trenul pleacă”.

EMBEDDINGS · OPTIMIZARE

Vectori normalizați: cosinusul devine produs scalar.

Normalizăm fiecare embedding la lungimea 1: â = a / ‖a‖. Atunci cos(a,b) = â · b̂, fără a mai calcula normele la fiecare comparație.

FĂRĂ NORMALIZARE

Cosine similarity

score = dot(a, b) / (norm(a) * norm(b))

Necesită norme și împărțire dacă nu au fost precalculate.

VECTORI NORMALIZAȚI

Dot product

a = a / np.linalg.norm(a)
b = b / np.linalg.norm(b)
score = np.dot(a, b)

Mai simplu și adesea mai rapid la multe comparații; normalizarea are și ea un cost inițial.

Într-un index vectorial, normalizarea poate fi făcută o singură dată la ingestie. Atenție: produsul scalar nu este egal cu similaritatea cosinus dacă vectorii nu au normă unitară.

RETRIEVAL · INFRASTRUCTURĂ

Unde stocăm milioane de vectori?

VECTOR DATABASE

Milvus ↗

Indexare vectorială la scară mare, căutare aproximativă ANN și filtrare pe metadata.

POSTGRESQL

pgvector ↗

Extensie PostgreSQL pentru vectori și operatori de distanță; indecși HNSW / IVFFlat. Păstrezi SQL, joins și datele relaționale.

ALTE OPȚIUNI

Qdrant ↗ · Weaviate ↗

Servicii specializate pentru căutare vectorială și filtrare hibridă.

Pentru 20 de documente: NumPy + cosine similarity. Pentru milioane: index ANN (aproximativ), metadata filters și compromisuri între latență, memorie și recall.

import os, requests, numpy as np
texts = ["Pisica doarme pe canapea", "Motanul se odihnește",
         "Am cumpărat un bilet de tren"]
r = requests.post("https://openrouter.ai/api/v1/embeddings",
  headers={"Authorization": "Bearer " + os.environ["OPENROUTER_API_KEY"]},
  json={"model":"qwen/qwen3-embedding-8b", "input":texts}, timeout=90)
r.raise_for_status()
v = np.array([x["embedding"] for x in sorted(r.json()["data"], key=lambda x:x["index"])])
v = v / np.linalg.norm(v, axis=1, keepdims=True)
print(np.round(v @ v.T, 3))  # matrice de similaritate cosinus

GENERARE DE IMAGINI · DIFFUSION

Cum învață un model să transforme zgomotul în imagine?

La antrenare, pornim de la imagini reale și adăugăm treptat zgomot. Modelul învață să prezică zgomotul adăugat, minimizând o funcție de eroare.

Imagine reală x₀→+ zgomot ε→Imagine zgomotoasă xₜ

Funcția de pierdere

L = E[‖ε − εθ(xₜ, t, text)‖²]

Optimizăm diferența dintre zgomotul real și zgomotul prezis de rețea (o formulare clasică DDPM).

Generare: procesul invers

Pornim de la zgomot aleator și eliminăm iterativ zgomotul estimat, condiționat de prompt, până obținem o imagine.

Diffusers: tutorial ↗

GENERARE DE IMAGINI · DIFFUSION

Din zgomot în imagine: diffusion și latent space.

Zgomot aleator→Denoising iterativ→Reprezentare latentă→Imagine
DIFFUSION

Învățăm să eliminăm zgomot

La generare, modelul pornește de la zgomot și rafinează repetat o reprezentare ghidată de prompt.

LATENT SPACE

Compresie utilă

În latent diffusion, procesul operează într-un spațiu comprimat, apoi un decoder reconstruiește imaginea. Mai ieftin decât denoising direct pe pixeli.

EXEMPLE

Familii de modele

HUGGING FACE · EVALUARE

Leaderboard ≠ adevăr universal.

Un benchmark este un eșantion de sarcini. Rezultatele depind de date, metrică, limbă și condițiile de evaluare.

METRICI

Clasificare

Accuracy: proporția tuturor predicțiilor corecte; poate induce în eroare pe clase dezechilibrate.

Precision: dintre exemplele prezise pozitiv, câte sunt într-adevăr pozitive: TP/(TP+FP).

Recall: dintre exemplele pozitive reale, câte sunt detectate: TP/(TP+FN).

F1: media armonică dintre precision și recall: 2PR/(P+R).

Top-k în câteva linii.

import numpy as np
from sentence_transformers import SentenceTransformer
model = SentenceTransformer(
  "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
)
texts = [r["text"] for r in records]
vectors = model.encode(texts, normalize_embeddings=True)
query = model.encode(["curaj și perseverență"], normalize_embeddings=True)[0]
scores = vectors @ query
for i in np.argsort(scores)[-3:][::-1]:
    print(round(float(scores[i]), 3), texts[i])
